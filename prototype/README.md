# 动态艺术签名 · Web 原型 v0.1

用来验证「观感」的可交互原型，不是最终 App。手机浏览器直接打开即可。

## 怎么打开

预览服务已在本机 8765 端口启动：

```
http://127.0.0.1:8765/
```

如果手机浏览器打不开 127.0.0.1，改用手机局域网 IP：

```
http://<手机IP>:8765/
```

重启服务（如果关了）：

```bash
cd /root/workspace/prototype && python3 -m http.server 8765 --bind 0.0.0.0
```

  带眨眼/折耳）、光点入场与离场、下划线 lift、发光、画幅/时长/背景可调。

## 这版验证的核心技术

需求文档里最大风险是「逐笔书写」——真 App 里要按笔顺把字"写"出来。

这版原型验证了**可行的做法**（对应需求文档 §7.3 方案 B）：

```
① 把艺术字体字形栅格化 → ② Zhang-Suen 细化提取 1px 骨架
③ 骨架按分叉点拆成子笔画 → ④ 用楷书笔顺数据给子笔画排序
⑤ 笔尖沿每段骨架推进，遮罩 ∩ 字形 → 逐笔写出来
```

关键点：**揭示的形状来自艺术字体自己的骨架**，不是套楷书轮廓。
所以覆盖率在 70–99%（末帧由收笔补齐到 100%）（`tools/diff.mjs` 实测），换任何字体都不会"写坏字形"；
而**书写顺序**来自真实楷书笔顺数据，所以"写"的先后是对的。

这同时验证了需求文档 §7.2 的核心架构：**字形层 / 笔顺层解耦** —— 同一套骨架管线能驱动全部 11 套字体。

### 书写手感（v0.2 重做）
用户反馈"书写不顺畅、没有笔锋"，做了三处重写：

1. **碎段先合并再排序**：原先是先排序后合并，同一笔会被拆成几段、分别排到不同时间，
   画面上就会出现"孤立的小点""不跟笔画走"。现在是先按连通性合并成完整笔画，再排笔顺。
2. **变宽缎带 + 方向压力 + 笔尖收锋**：不再是圆点拼接，而是沿笔画左右偏移围成的闭合多边形；
   竖笔略粗、横笔略细（模拟侧锋），笔尖处收细形成出锋。正在写的那一笔单独一层渲染，
   否则笔尖会被反复叠加成圆头。
3. **按弧长推进 + 速度微波动**：笔尖按"走过多少距离"推进，并叠加轻微速度起伏，避免匀速机械感。

客观指标（`node tools/smooth.mjs`，60fps 模拟）：
- 空帧率（无新墨迹的帧）从 **22–58% 降到 4–10%**
- 碎段数从 40–50/2字 降到 25–31/2字

### 签名周边功能（v0.3）
参考项目的"装饰 + 首尾动画"思路做成 4 个小功能：装饰图案（emoji + 各自小动作）、
落款印章（方/圆、按压回弹）、落款日期、下划线；另外做了**情侣双人签名**（两个名字 + 中间爱心）。
装饰的时间轴排在书写完成之后：书写 → 装饰弹出 → 下划线 → 印章按压 → 落款日期。

> 注意：装饰图案用 emoji 绘制，Node 侧自检环境没有 emoji 字体（截图里会显示成方框），
> 手机浏览器 / 正式 App 里是正常彩色图案。

### 参考项目
笔刷的"方向压力 + 变宽缎带 + 速度波动"思路参考了 [tangyx527/tyx-signature](https://github.com/tangyx527/tyx-signature)（MIT）。
它的做法是给拉丁字母手工做笔画字体 + 定位数据；中文无法穷举，所以本项目改用**从艺术字体自动提取骨架**来达到同样的书写效果。

## 已知限制（原型阶段，不影响方向判断）

1. **骨架计算有耗时**：单字 15–95ms（Node），手机上约翻 2–3 倍，首次输入新名字会有一次性「逐笔分析中」提示，之后走缓存。
2. **笔顺排序是启发式**：用楷书笔顺给骨架子段排序，遇到草书等结构差异大的字，顺序可能和真人书写略有出入（形状不受影响）。
3. **没有排版/落款/模板**：原型只验证单行动效，竖排、印章、落款、模板体系按需求文档后续做。
4. **导出只有 PNG**：GIF/MP4 需要编码器，属于 Android 阶段的工作。
5. **字体全量随包**：手机上 11 套字体共 21MB；正式版要子集化到每套 1–3MB（需求文档 §7.7）。
