# 包体与性能优化评估（实测版）

> 基于 **v0.3.9 真实 APK（64.4MB）** 拆包统计，2026-11-13。
> 原则：**不牺牲功能、不降低观感/导出画质、不减少字体或动画种类**。

## 1. 当前 APK 成分（实测）

| 成分 | 压缩后 | 原始 | 文件数 | 占比 |
| --- | --- | --- | --- | --- |
| 字体 fonts | **47.2M** | 71.3M | 11 | **73%** |
| 笔顺数据 strokes | **14.3M** | 30.8M | 9574 | **22%** |
| DEX 代码 | 1.1M | 3.1M | 1 | 1.7% |
| Android 资源 res | 0.4M | 0.4M | 49 | 0.6% |
| Web 代码（js/html/vendor/port） | 0.1M | 0.2M | 13 | 0.2% |
| 其它（arsc/META-INF） | ~0 | ~0 | 6 | ~0 |
| **合计** | **64.4M** | | | |

结论：**95% 是字体 + 笔顺数据**，代码和资源已经很小，优化只能从这两块下手。

## 2. 三个已确认的"纯浪费"（改完不掉质量）

### ① 已删除的 4 套字体仍在打包 —— 白占 ~10.5MB
应用启用的字体只有 7 套（志莽行书 / 柳建毛草 / 龙藏 / 霞鹜文楷 / 庆科黄油 / 悠哉 / 得意黑），
但 `copy-assets.sh` 是 `cp fonts/*.ttf`，把用户已要求删除的 4 套**也打进了 APK**：

| 白打包字体 | 原始 | APK 内 |
| --- | --- | --- |
| mashanzheng.ttf（马善政） | 5.6M | 3.9M |
| markergothic.ttf（霞鹜漫黑） | 3.5M | 2.0M |
| zcoolxiaowei.ttf（站酷小薇） | 6.0M | 3.5M |
| zcoolkuaile.ttf（站酷快乐） | 1.4M | 1.1M |
| **合计** | **16.5M** | **10.5M** |

修法：打包脚本改成**按 FONTS 列表拷贝**。零风险、零质量损失。

### ② 笔顺数据里 70% 的字段没被使用 —— 白占 ~9.7MB
每个字 JSON 有 `strokes`（笔画轮廓路径，1856 字符）、`medians`（中心线，540 字符）、`radStrokes`。
当前引擎（骨架方案）**只用 medians** 给笔顺排序，`strokes` 轮廓已完全不再使用。

| 方案 | 原始 | gzip（≈APK 内） |
| --- | --- | --- |
| 现状（三者全存） | 30.8M | 12.0M |
| **只存 medians** | **6.3M** | **2.3M** |
| 进阶：varint 增量二进制 | 1.8M | ~0.6M |

修法：打包时剥掉 `strokes`/`radStrokes`（或直接改 `fetch-assets` 只存 medians）。
**省 ~9.7MB，零质量损失**（轮廓本来就没参与渲染）。

### ③ 字体格式：TTF → WOFF2 —— 再省 ~21MB
实测（7 套启用字体，子集到 9694 字后转换）：

| 字体 | 原始 TTF | 子集 TTF | **子集 WOFF2** |
| --- | --- | --- | --- |
| zhimangxing | 3.9M | 3.9M | **2.2M** |
| liujianmaocao | 4.7M | 4.7M | **2.2M** |
| longcang | 4.9M | 4.9M | **2.8M** |
| lxgwwenkailite | 13.3M | 5.0M | **2.2M** |
| zcoolhuangyou | 7.9M | 7.2M | **2.2M** |
| yozai | 14.5M | 5.6M | **2.9M** |
| smileysans | 2.5M | 1.9M | **0.9M** |
| **合计** | **51.8M** | 33.2M | **15.4M** |

（APK 里字体现在占 36.8M，换 WOFF2 后 ≈15.4M）
- 单靠"按字数裁剪"只省 18M（因为这几套字体本身也就 8000 字左右，裁不动）
- **WOFF2 压缩才是主力**：WOFF2 自带 Brotli，APK 不会再压它，直接省 ~21MB
- 子集范围建议：9574 个有笔顺的字 + ASCII + 常用标点 + GB2312，共 9694 字，和现在能渲染的范围一致

## 3. P0 已实施结果（实测 assets）

已改完后重新打包统计：

| 成分 | 改前（APK 内） | 改后（assets 原始） | 预计 APK 内 |
| --- | --- | --- | --- |
| 字体 | 47.2M（11 套） | **51.8M（7 套原始）** | ~36.8M |
| 笔顺数据 | 14.3M | **6.3M（仅中心线）** | ~2.3M |
| 代码/资源/DEX | 1.6M | 0.2M + dex/res | ~1.6M |
| **预计 APK** | **64.4M** | — | **≈ 41M（−37%）** |

顺带修掉一个隐藏 bug：**得意黑的字体路径写错**（配置 `SmileySans-Oblique.ttf`，实际文件 `smileysans.ttf`），
这套字体从加入以来一直没加载成功；修复后 7 套字体全部可用（验证：覆盖率 78–97%，得意黑 80–95%）。

## 4. 汇总：预计包体

| 步骤 | 预计 APK | 相对现在 |
| --- | --- | --- |
| 现状 | 64.4M | — |
| ① 去掉 4 套死字体 | ~53.9M | **−10.5M** |
| ② 笔顺只存中心线 | ~42.2M | **−11.7M**（累计） |
| ③ 字体转 WOFF2 子集 | **~20.8M** | **−43.6M（−68%）** |

## 4. 风险与验证（必须真机确认）

| 项 | 风险 | 兜底 |
| --- | --- | --- |
| WOFF2 | Android WebView 的 `FontFace` 对 WOFF2 支持需实测（Chromium 内核理论支持；资源 MIME 可能需显式设置） | 若失败，退回 TTF 子集（33.2M，仍省 ~3.6M）；或保留 2 套 TTF + 5 套 WOFF2 混合 |
| 字体子集 | 用户名字里有超出 9694 字的生僻字会缺字 | 字体栈加系统回退 `fontFamily: "Sig", sans-serif`，缺字用系统字体显示（不再是空白/豆腐块）；提示"该字使用系统字体" |
| 笔顺瘦身 | 无（轮廓本来没用） | — |
| varint 二进制包 | 需要改加载器，收益仅再 ~1.7M | 放到第二阶段，不急 |

## 5. 非包体的优化空间（提升体验，不改功能）

1. **首屏**：字体已按需加载；但 `data/strokes` 首次按字 fetch，输入名字时会有一次网络（本地 asset）读取 —— 可改成**打包成单文件 + 命中索引**，减少 9574 个 asset 条目的 open 开销（APK 里文件条目本身也占 zipalign 空间）
2. **渲染**：DPR 固定 1.5；可做**自适应 DPR**（测得 fps<45 自动降到 1.0），低端机更稳
3. **静止态**：已做降频（每 6 帧）；可进一步在完全静止 3s 后停 rAF（省电），触摸/参数变化再恢复
4. **骨架计算**：结果已缓存 localStorage；可再加**构建期预生成高频姓氏骨架**（几百字，增加 ~100–300KB，换来首次输入姓氏从 ~100ms 降到 0）
5. **GIF 导出**：当前逐帧量化在主线程；可加 Floyd–Steinberg 抖动提升渐变观感（体积 +10~15%），或提供"高/标准"两档
6. **MP4 导出**：bitrate 目前按公式固定，可按画幅给 2/4/8Mbps 三档
7. **内存**：笔顺只存中心线后，JSON 峰值内存从 ~30M 降到 ~6M（顺带收益）
8. **构建**：release 变体开 R8（`isMinifyEnabled=true` + shrinkResources）可再省 0.5–1MB，但需另建签名配置；当前发的是 debug 包，签名每次不同，升级必须卸载（可以做一个固定 debug keystore 解决"每次要卸载"的痛点）

## 6. 建议实施顺序

- **P0（零风险，先做）**：① 死字体移除 + ② 笔顺瘦身 → 64.4M → ~42M，**改动只涉及打包脚本**，一次构建即可验证
- **P1（需真机 1 次验证）**：③ WOFF2 子集 → ~21M
- **P2（可选）**：varint 二进制包、自适应 DPR、静止停 rAF、GIF 抖动开关、固定 debug keystore
